## 1. 제품 한 문장 정의

**SPIN 은 파워체어 풋볼 코치가 체육관에서 무릎 위 태블릿으로 자석 전술판을 밀듯이 판을 만들고, 그 판을 그대로 선수 앞에 시연하고 종이로 뽑아 나가는, 서버 없는 오프라인 전술판이다.**

세 어절이 이 문장의 전부를 지탱한다 — *자석 전술판처럼*(물성이 UI 보다 앞선다), *체육관에서*(7인치 가로가 기준 자세다), *서버 없이*(REQUIREMENTS.md:19).

## 2. 확정 IA

### 2.1 원칙 세 줄

1. **화면 키를 늘리지 않는다.** `home`→`board`, `library`→`drills` **개명만** 한다. `present` 는 화면 키로 남기고 레일에서만 뺀다. `SCREEN_ORDER` 는 4개 그대로다. → `screens.ts:5-8` 의 *"2026-08-09 재편: editor 를 별도 화면 키에서 없앴다"* 결정과 그 수호 테스트(`screens.test.ts:13-18`)가 **초록불로 남는다.** 안 2 가 `board`/`edit` 로 쪼개며 그 결정을 되돌리려던 지점이 정확히 여기이고, 이 안이 갈라서는 유일한 구조적 분기다.
2. **[보드]는 화면이 아니라 "지금 손에 든 판"이다.** 자유 전술판이든 드릴 편집이든 [보드]가 현재 페이지인 것이 **참**이 된다. 그래서 `aria-current='page'`(AppRail.tsx:71,76)가 거짓말을 멈춘다. *무엇이 떠 있는가* 는 화면 키가 아니라 **헤더 제목**이 말한다('자유 전술판' / 드릴 제목).
3. **레일 활성 판정은 명시적 상수 맵으로 접는다.** `SCREEN_TO_RAIL = { board:'board', drills:'drills', present:'drills', settings:'settings' }`. AppRail 은 여전히 화면 키만 보고 StageTarget 을 모른다 — 레일이 편집기 상태에 결합되는 것을 막기 위해서다(안 2·안 3 공통 이식).

### 2.3 히스토리 계약 확장

```ts
type NavTarget =
  | { kind: 'board' }
  | { kind: 'drill';   id: string }
  | { kind: 'session'; id: string }
  | { kind: 'tab';     tab: 'drills' | 'sessions' };

interface NavEntry { screen: Screen; depth: number; target?: NavTarget }
```

- 전부 structured-clone 안전한 평문. 함수·클래스를 싣지 않는다.
- `isNavEntry` 가드와 `SCREEN_SET` 화이트리스트를 함께 갱신하고, **구 키 `'home'`/`'library'` 를 신 키로 접어 주는 한시적 관용 경로**를 같은 커밋에 넣는다 — 안 넣으면 기존 사용자의 `history.state` 가 전부 무효로 판정돼 뒤로가기 이력이 초기화된다.
- **개명과 target 확장은 반드시 한 커밋**이다(심사관 2 [중대]). 두 번에 나누면 히스토리 초기화가 두 번 일어난다.
- 이득: 체육관에서 태블릿이 리로드돼도 시연이 안 끊긴다. 지금은 `history.state` 는 `'present'` 로 복원되는데 `presentTarget` 은 null 로 리셋돼(AppShell.tsx:162) *"시연할 드릴을 목록에서 선택하세요"* 빈 화면이 뜬다.

## 3. 초·중·고급 수용 장치 — 확정: **트레이 서랍**

**닫힌 서랍 2개 + 상시 노출된 손잡이 + 자동 개방 + 난이도 그룹 정렬 + seed 드릴 3개.**

┌────────────────────────────────┐
│ [보드][드릴][설정]  ← narrow 에서만, 헤더가 가져감(2.2 참조)  │

**핵심 불변식 세 개**

1. **접힌 것은 위치를 옮기지 않는다.** 서랍이 열려도 위쪽 항목(선수·공·콘·선택·지우개)의 좌표가 한 픽셀도 안 움직인다. 발 마우스·입 젓가락 사용자는 표적의 **절대 위치로 공간 기억을 만든다** — 조준 대상이 사용 중에 이동하는 UI 는 그 자체로 비용이다.
2. **잠긴 기능은 0개다.** 서랍이 닫혀 있어도 단축키 R·P·T 는 살아 있고, 누르면 그 도구로 전환되며 **그 순간 서랍이 영구히 열린다.**
3. **남의 드릴을 열면 그 드릴이 쓰는 말에 맞춰 서랍이 자동으로 열린다.** 고급자가 만든 것을 초보자가 받아 여는 순간 필요한 도구가 이미 준비돼 있다 — 지금 끊겨 있는 '고급자→초보자' 전달 경로의 절반이 이걸로 열린다.

**저장 비용**: `prefs.tray = { draw: boolean, note: boolean }` + `seeded: boolean`. `CURRENT_PREFS_SCHEMA`·`validatePrefs`·`PREFS_MIGRATIONS` 3종 세트를 한 번 손보고 끝. `index.html:26-33` 부트 스크립트가 전제하는 `spin.prefs.theme` 최상위 문자열 불변식은 건드리지 않는다.

**seed 드릴 3개(초/중/고)** 는 판이 아니라 **목록(drillRepo)에** 심는다 — *"전술판은 비운 채 만든다"* 가 2026-08-10 지시로 못박혀 있다. 그리고 그 seed 의 `step.note` 가 조작 설명을 겸한다(안 2 이식): `PresentRunner.tsx:487-492` 가 코치에게 `step.name`/`step.note` 를 크게 읽어 주므로 **"첫 드릴을 시연한다 = 앱 사용법을 시연받는다"** 가 공짜로 성립한다. 튜토리얼 오버레이 프레임워크(런타임 deps 3개 원칙 위반) 없이 온보딩을 만드는 유일한 길이다.

**난이도는 정렬로만 쓴다.** `drill.level` 은 지금 저장·표시만 되고 필터·정렬 어디에도 안 쓰이는 장식 필드다. 이것을 목록의 **그룹 헤더 정렬**로 쓴다 — 필터 드롭다운은 표적을 하나 더 누르게 하지만 그룹 헤더는 0클릭이다. 구현은 `DrillQuery` 쪽 요약 필드 직접 비교라 `SUMMARY_BUILD` 증가도, 호출자가 0인 `rebuildAllSummaries` 신설도 불필요하다.

### 4.2 새로 할 것 — P0 (판이 거짓말하는 것을 멈춘다. **선결 조건이다**)

**P0-1 · 겹친 휠체어가 스스로 벌어진다** — 원인은 코드가 아니라 **루프가 죽는 타이밍**이다. `endDrag` 는 substep 의 `Engine.update` **뒤에** 칩을 dynamic 으로 되돌리고 곧바로 `requestSettle` 을 거는데(index.ts:199-204), 그 프레임 말미의 정지 판정(loop.ts:44)이 `allAtRest()==true` 를 보고 즉시 `stop()` 한다 — **칩이 dynamic 이 된 뒤의 `Engine.update` 가 단 한 번도 실행되지 않는다.** matter 의 겹침 해소는 위치 보정이라 속도를 만들지 않으므로(Resolver.js:144-146) 깊이 12.5px 로 겹친 두 칩도 rest 다. 실측: endDrag 시점 depth 12.50 / isSettled()=true → 한 프레임만 더 돌리면 2.73 → 200프레임 뒤 완전 분리.

- 조치: `endDrag` 후 **겹침이 남아 있는 동안만** 루프를 붙잡는다. `allAtRest` 의 의미를 바꾸지 않는다(world.test.ts:400-406 이 지금의 버그를 계약으로 굳혀 놓았으므로 그 테스트는 값을 갱신하되, 조기 종료 골든 테스트 269-307 는 초록불로 남겨야 한다).
- **종료 조건을 반드시 명세한다**(심사관 2 지적): 상한은 기존 `PHYS.settleMaxMs = 8000`(constants.ts:130). 그 안에 안 풀리면 **기하 분리 폴백**(P0-3 의 OBB escape)을 1회 강제하고 루프를 끝낸다. 수치 오차로 깊이가 영원히 0 이 안 되는 경우에 배터리를 태우지 않는다.
- **[2026-08-12 실측 정정] 배터리 논거의 실제 최악값은 8초가 아니라 12초다.** 8000 은 *정착 구간*의 상한이고, 손뗌→멈춤 전체는 릴리스 체이스(`INTERACT.releaseChaseMs = 4000`)가 앞에 붙어 `4000 + 8000 = 12000 ms` 다. 코드는 이 값을 이미 알고 있다(`useEditorPointer` 의 자동저장 억제 창이 정확히 12000 으로 열린다). 검증 실측: 정착만 걸린 배치 8000.0 ms · 체이스만 걸린 배치 4000.0 ms · 둘 다 걸린 배치 8416.7 ms.
- **[2026-08-12 실측 정정] 완료 판정은 `depth === 0` 이 아니라 `depth ≤ PHYS.overlapRestPx`(0.5) 다.** 벽에 낀 배치에서 잔여 겹침 0.3212 px 이 남는다. 문턱이 0 일 수 없는 이유는 matter 가 접촉을 slop(`0.05 × 0.5 = 0.025 px`)만큼 파묻힌 채로 재우기 때문이다 — 0 이면 정상적으로 맞닿아 선 칩이 영영 '겹침'으로 읽혀 손 뗄 때마다 8초를 태운다. 후속 작업자가 `toBe(0)` 을 계약으로 인용하면 깨진다.

**P0-2 · 놓은 자리는 그대로 있다 (정착 후 재커밋)** — `commitDragResult` 는 `handle.end()` 직후 **동기적으로** 스냅샷을 읽는다(useEditorPointer.ts:419,433). 릴리스 체이스는 최대 4초이고 속도 제한이 켜져 있으면 선속 69.4 px/s 라 750px 코트 횡단에 10초가 걸린다. 그래서 화면에서는 칩이 손을 따라와 멈췄는데, 스텝을 넘겼다 돌아오면 손 떼던 순간의 자리로 되돌아간다(world.load 가 epoch 마다 옛 좌표로 바디를 재생성한다).

- 조치: `PhysicsWorldApi` 에 '정착 완료' 통지를 열고 `PLACE_SETTLE` 로 **present 만 교체**한다. 히스토리 경계를 새로 열지 않는다 — *'드래그 1회 = undo 1회'* 계약(history.ts:72-80) 유지.
- **[A-4 정정] `epoch` 을 올려서는 안 된다.** `EditorProvider.tsx:108-113` 은 epoch/stepId/cast/courtMode 가 바뀔 때마다 바디를 전량 재생성한다. PLACE_SETTLE 이 epoch 을 건드리면 *정착 → world.load → 재정착* 무한 루프가 된다. "present 만 교체"라는 표현으로는 이 위험을 못 막으므로 **epoch 불변을 완료 판정에 명시적으로 단언한다.**
- **[A-5 정정] autosave 가 드래그 1회당 두 번 쓴다.** `useAutosave.ts:38-40` 은 `state.present` 참조 동일성으로 판단하고 800ms 디바운스한다. 정착이 800ms 를 넘으면 IDB CAS 쓰기가 2회가 되고 두 번째가 `expectedUpdatedAt` 을 물고 들어가므로 **다중 탭 conflict 판정 경로를 함께 봐야 한다.** 정착 통지에 "저장 억제 창"을 두거나 두 번째 쓰기를 CAS 재시도로 흡수하는 것 중 하나를 고른다.
- **이게 P0-1 보다 먼저 성립해야 한다**: 겹침을 고쳐도 분리된 결과가 저장되지 않으면 다시 겹친 채로 로드된다.

**P0-3 · 판 밖은 존재하지 않는다** — bounds 로 막히는 것은 드래그되는 칩뿐이고(drag.ts:90), 밀려나는 쪽 칩에는 `escapePinnedAll` 이 적용되지 않는다(world.ts:264-270 이 `label==='chair'` 를 radius undefined 로 건너뛴다). 실측에서 밀린 칩이 x=-5(차체 뒤끝 -12.5)로 나가 그대로 굳었다. `obb.ts` 의 `searchTangentEscape` 를 원 기준에서 **OBB 대 OBB/벽**으로 확장한다.

### 4.4 새로 할 것 — P2

**P2-1 · 판의 테두리를 잡으면 판이 움직인다** (안 3 이식, 충돌 해소판)
- 코트 바깥 마진 **1.5 m = 37.5 월드px** 띠가 곧 판의 프레임이다(2026-08-10 마진 확장의 부산물).
- **심사관 1 이 [치명]으로 짚은 `edgePanBandPx = 56` 충돌은 이렇게 닫는다**: 마진 띠 전체가 edgePan 띠(56 CSS px) 안에 들어가므로 좌측만의 문제가 아니다. 그래서 겹치지 않게 **시작 지점으로 나눈다** — **경기면(surface) 밖 마진에서 시작한 드래그 = 판 이동 / 경기면 안에서 시작 = 고무줄 선택.** edgePan 은 고무줄이 이미 시작된 뒤에만 도는 기능이므로 그대로 유효하다.
- 키보드 팬 = **Ctrl/Cmd + 방향키**. 방향키 소비자 셋(전역 스텝 이동 ←→ / 개체 이동 / 배치 커서)과 Shift·Alt 조합이 이미 차 있으므로 Ctrl 만 비어 있다(지금 Ctrl 은 Z/S/D/±/0). 팬 델타는 반드시 `screenDeltaToWorld(rot)` 를 통과시킨다.
- 더블클릭 팬(350ms/12px)은 **남긴다** — 발 마우스에서 가장 실패하기 쉬운 입력이지만, 제거는 기존 사용자 회귀다. 주 경로만 옮긴다.

**P2-2 · 저배율 2존 모드** (안 3 이식, 심사관 2 권고대로 **자동 게이트가 아니라 명시 토글**)
- 접근성 설정의 토글 1개. 켜면 **차체 전체 = 이동**, **차체 밖 앞뒤 가이드 = 회전·견인**.
- 왜 필요한가: 화면에 그려지는 핸들은 towRear·towFront **둘뿐**이고(ZoneHandles.tsx:26) *'차체 위 핸들은 등번호를 가려서 뺀다'* 는 2026-08-11 지시가 있다. 그래서 *'저배율 터치에서는 직접 잡기를 끄고 핸들만 쓴다'* 는 죽은 배선(`handlesVisible` / `INTERACT.zoneDirectMinPxPerUnit = 1.28`, 반환값 소비처 0)을 그대로 되살리면 **터치 사용자가 이동·회전 수단을 전부 잃는다.** 2존 병합이 이 모순에 대한 유일하게 실행 가능한 답이다.
- 왜 자동이 아닌가: 확정 배율 분포(7인치 0.663 / narrow 0.891 / PC 오버레이 1.151 / PC 핀 0.899 / 27인치 1.675)는 문턱 1.28 을 여러 번 넘나든다 — 자동이면 **줌이 조작 규칙을 바꾸는 사고**가 된다. `handlesVisible` 의 `forced` 인자를 이 토글에 연결해 죽은 배선을 되살리되 자동 문턱 판정은 끈다.

**P2-3 · 스텝 = 판을 찍어 쌓은 사진 뭉치** (안 3 이식) — TransportBar 의 스크러버 트랙 자체를 **스텝 썸네일 칩 줄**로 바꾼다. 끌어서 순서 변경, [한 장 더 찍기] 1버튼. 지금 스텝 조작은 인스펙터의 26×22 / 22×22 버튼이라 WCAG 24px 도 못 맞추는데, 인스펙터를 오버레이로 내리면 그 문제가 악화되므로 사진 뭉치가 그 자리를 메운다. 높이는 44px 유지 — 세로 크롬을 늘리지 않는다.

**P2-4 · 3m 링 (2-on-1)** — 공을 따라다니는 반경 3 m(75 월드px) 원. 같은 팀 둘이 그 안에 들어가면 링이 붉어진다. **반드시 TransformWriter 팔로워로 등록한다** — React state 로 그리면 §6.1 규칙 1 위반이고, ZoneHandles 가 같은 실수로 '핸들만 제자리에 남는' 버그를 낸 전례가 있다(ZoneHandles.tsx:6-10). 시연 화면은 물리가 아니라 `sampleDrill` 보간 경로라(PresentStage.tsx:1) 같은 오버레이를 **두 경로에 각각** 배선해야 한다.

## 5. 기기 대응

### 5.1 분기는 boolean 두 개뿐

```
useIsPortrait()  — 기존. 창 기준. matchMedia('(orientation: portrait)')
useIsNarrow()    — 신설. 창 폭 < 1100px
```

- 레이아웃 값이 CSS 가 아니라 **.tsx 안의 인라인 style 객체**에 흩어져 있으므로(src/styles 는 4개 파일뿐이고 저장소 전체 `@media` 는 `prefers-reduced-motion` 1건) 미디어쿼리로는 못 얹는다. 두 boolean 이 style 상수 쌍을 고른다.
- **회전(rot)은 코트 영역 기준, 레이아웃 판정은 창 기준** 이라는 분리를 깨지 않는다(useIsPortrait.ts:4-10). 묶으면 패널을 내려 코트가 넓어졌는데도 여전히 돌아버린다.
- **narrow 전환은 컴포넌트가 아니라 컨테이너만 바꾼다**(안 2 이식) — 같은 ToolRail·InspectorPanel **인스턴스**를 다른 부모에 넣는다. 재마운트하면 인스펙터 펼침 상태가 날아간다(EditorWorkspace.tsx:242-243 이 이유를 기록해 뒀다). [고정] 핀 토글에도 같은 규칙이 적용된다.
- `narrow === false` 면 PC 경로 코드가 **한 줄도 안 바뀐다.**

### 5.4 터치 타깃

**폭에 여유가 남는다는 사실이 이 절의 핵심이다.** 1024×600 에서 세로가 제약이므로(468/525 = 0.8914 < 907/825 = 1.0994) 코트가 실제로 쓰는 폭은 735px, **남는 폭이 172px** 이다. 따라서:

> **트레이를 93 → 264 까지 넓혀도 축척 손해가 0 이다.** '큰 터치 타깃(56px)을 켜면 코트가 줄어든다'는 걱정은 narrow 가로에서 성립하지 않는다.

- 안 3 의 실측 *"트레이 15px 확대의 축척 손해는 0.7%"* 를 확인했고, 이 구성에서는 **0%** 다.
- **트레이 칩 크기를 `var(--hit)` 파생으로 만든다.** 현재 `TRAY_CHIP_H = 33`, `TRAY_CHIP_W = 33×25/37.5 = 22`, 상자 = 30×39 — **이 앱 주력 조작(끌어다 놓기)의 손잡이가 44 미달이다.**
  - `--hit: 44` → 칩 상자 **44×60**(H=54, W=36), `TRAY_CHIP_ROW_MAX = 44×2+5 = 93`
  - `--hit: 56` → 칩 상자 **56×78**(H=72, W=48), `ROW_MAX = 117`
- **`--hit` 을 실제로 배선한다**: 지금 `--hit`(tokens.css:117 = 44 / :125 = 56)은 Button·Toggle·Segmented·Modal·Drawer·Toast·인스펙터 행 9곳에만 걸려 있고 **StageControls(44 하드코딩)·TransportBar(44/48)·BoardBar(44)·ToolRail 칩(30×39)·스텝 칩은 한 픽셀도 안 커진다.** 설정 화면의 설명문이 사실과 다른 상태다.

**코트 위 화면 히트 지름** (공식: 공 `min(8.25s+12, 22.5s)` · 콘 `min(6.25s+12, 17.5s)` · 메모 `min(12, 25s)` — `pickPadCssPx=6`, `HIT_R_MAX_PX` 로 실측 검산 완료)

| s | 공 | 콘 | 메모 | 차체 내부 존 밴드 |
|---|---|---|---|---|
| 0.6073 (현재 1024×600) | 15.0 | 15.6 | 12.0 | 11.4 |
| **0.8914 (확정 1024×600)** | **19.4** | **15.6** | 12.0 → **22.0** | **16.7** |
| 0.6629 (800×480) | 14.9 | 11.6 | 12.0 → 22.0 | 12.4 |

→ **WCAG 24px 에 여전히 못 간다.** `HIT_R_MAX_PX` 는 §6.5 blocker + `hitTest.contract.test.ts:32` 로 잠겨 있어 올릴 수 없다. 그래서 남은 간극은 **2단 히트(P1-2)** 로 메운다 — 빈 곳을 탭하면 44 CSS px 안에서 재탐색한다. 그리고 존 밴드 16.7px 는 손가락 접촉면(약 40px)에 못 미치므로 **2존 모드 토글(P2-2)** 이 그 자리를 메운다.

### 5.5 대체 경로 명세 (심사관 1 [치명] 4번의 나머지 절반)

*"코트 위 공·콘 정밀 집기를 뺀다"* 는 우회는 대체 경로가 검증되어야 성립한다. 확정:

1. **2단 히트가 1차 대체다.** 44px 안이면 잡힌다 — 순회가 아니다.
2. **Alt+←/→ 순회를 종류별로 자른다.** 지금은 전체 순회라 휠체어 8 + 공 1 + 콘 6 이 있으면 목표까지 최대 15회다. 확정 규칙: **(a)** 도구가 특정 종류로 잡혀 있으면 그 종류만 순회, **(b)** 아니면 **최근 조작 개체를 맨 앞**에 두고 그다음은 생성순. 콘 6개 중 방금 만진 것으로 돌아가는 데 1회다.
3. **트레이 반환이 3차다.** 코트 개체를 트레이 위에 놓으면 판에서 빠지는 경로는 이미 있다(useEditorPointer.ts:41-51, 415-432) — 다만 이 안내가 지금 `title` 속성 + `aria-hidden="true"` 조합이라(ToolRail.tsx:335-343) **마우스 호버로만 존재한다.** `aria-hidden` 을 sr-only 설명 한 줄로 바꾸고 도움말에도 적는다.

### 5.6 트레이 키보드 활성화 복구

`ToolRail.tsx:283-285` 의 `onClick: () => { if (!onItemPointerDown) onTap(); }` 때문에 프로덕션 배선 경로(EditorWorkspace.tsx:259 가 항상 배선한다)에서 **Enter·Space 가 아무 일도 하지 않는다** — 반증 실험으로 확인: `onArmPlayer` 0회, `onItemPointerDown` 0회. 트레이는 2026-08-11 재편으로 개체 배치의 **주 경로**가 된 곳이라 키보드·스위치·음성 사용자가 통째로 튕겨나가는 주 경로 고장이다.

조치: 조건을 그냥 풀면 마우스에서 이중 발화하므로 **`e.detail === 0`(키보드 활성화)만 통과**시킨다. `ToolRail.test.tsx:149-150` 이 `onItemPointerDown` 없는 경로를 이미 붙잡고 있으므로 **배선된 경로의 회귀 테스트를 함께 넣는다.**

## 6. 내보내기 3종

### 6.1 JSON — 앱이 읽는 문서. **두 종류만 남긴다**

**(a) 공유 파일**
- `spin:'drill'` — Drill 1개 통째(steps 전량). 코치끼리 주고받는 단위. **지금 그대로.**
- `spin:'session'` — 세션 + 참조 드릴 **실물** 동봉. 자기완결적이다. **지금 그대로.**

**(b) 기기 이사 파일 — 새 kind `'backup'`**
```
{ spin:'backup', envelope:1, app:'SPIN', exportedAt,
  payload: { drills: Drill[], sessions: TrainingSession[], prefs: Prefs, board: BoardSnapshot } }
```
- 지금의 '전체 내보내기'는 `library` 봉투 = `Drill[]` 뿐이라 **세션(IDB `sessions`)·설정(localStorage `spin.prefs`)·자유 전술판(`spin.board`)이 어떤 파일에도 안 들어간다.** 사용자는 백업했다고 믿고 있다가 브라우저 데이터를 지운 뒤에야 손실을 안다 — 이건 기능 부족이 아니라 **거짓말**이라 최우선이다.
- `library` kind 는 **읽기는 계속 지원**(기존 파일 호환), 쓰기는 중단. 목록 화면과 설정 화면의 중복 '전체 내보내기' 버튼 둘 다 제거하고 설정의 [기기 이사 파일 만들기] 하나로 모은다.
- 새 kind 는 `KNOWN_KINDS`·`SpinFile` 유니온·`prepareDrillImport` 의 kind 거부 경로·`storage/transfer.test.ts` 의 계약 표를 **함께 늘리는 방식으로만** 들어간다.
- 복원 경로는 `index.html:26-33` 부트 스크립트가 전제하는 **`spin.prefs.theme` 최상위 문자열 불변식**을 건드리지 않는다.
- `features/library/transfer.ts:61` 의 *"설정 파일은 설정 화면에서 가져오세요"* 안내가 지금은 존재하지 않는 화면을 가리키는 막다른 문구인데, 이 항목이 그 문구를 **사실로** 만든다.

**(c) 가져오기 보고 — 보고하되 묻지 않는다** (세 안이 같은 결론)
`prepareDrillCandidates` 는 migrate·validate 실패 항목을 `continue` 로 건너뛴다(transfer.ts:126,128). 10개짜리 파일에서 3개가 깨져 있어도 토스트는 '7개 가져옴'이라 말한다. `repairs` 도 `ImportCandidate` 에 담기기만 하고 화면에 안 나온다.
→ 결과를 **'7개 가져옴 · 3개 건너뜀 · 2개 자동 수정'** 으로 바꾸고 상세는 접힌 영역에. **다이얼로그 항목은 늘리지 않는다** — 3택에 항목이 늘면 입력 부담이 는다.

**(d) 저장 경로 2건 수정**
1. `navigator.canShare({files})` → `navigator.share` 를 1순위, `a[download]` 폴백. standalone PWA(`display:standalone`)로 홈 화면에서 띄운 iOS 에는 브라우저 크롬이 없어 **다운로드 UI 가 보이지 않는다** — 코치가 [내보내기]를 눌러도 파일이 어디 갔는지 알 수 없다. share 는 '저장 + 팀에 전송'을 한 동작으로 끝낸다(사용처 0건).
2. `files.ts:43-45` 의 `a.click(); a.remove(); URL.revokeObjectURL(url);` 를 **다음 틱으로** 미룬다. Safari 계열(iPadOS 포함)에서 다운로드 시작 전에 URL 이 회수돼 저장이 조용히 실패하는 형태이고, 이 경로가 **모든 내보내기가 모이는 유일한 출력구**다. jsdom 에서는 no-op 이라 **실기 iPad 확인이 반증 조건**이다.

### 6.2 PNG — 한 스텝, 한 장면

| 담긴다 | 안 담긴다 |
|---|---|
| 코트 라인 · 개체(번호·GK) · 화살표 · 메모 · 켜져 있으면 3m 링/2인 존 · 하단 캡션(드릴 제목 · 스텝 n/N · 스텝 이름) | 트레이 · 선택 링 · 핸들 · 격자 칸 라벨 · 존 음영 · `focus-ind-*` |

**기술 경로 (확정)**

1. **살아 있는 DOM 을 `XMLSerializer` 로 직렬화하는 순진한 경로는 쓰지 않는다.** `focus-ind-outer/inner` 노드는 스타일이 `a11y.css:27-39`(`opacity:0; fill:none; stroke:#000`)에만 있어서, 스타일시트 없는 SVG 로 떼면 SVG 기본값(fill:black, opacity:1)이 적용돼 **휠체어·공·콘·메모마다 검은 사각형이, 화살표마다 검은 띠가 덮인다.** `var(--accent)` 노드들(SelectionOverlay/ZoneHandles/ArrowHandles)도 해석 불가가 된다.
2. `PresentObjects.tsx:1-14` 가 문서화한 **'원본 파일을 안 고치고 바깥 `<g>` 를 소유하는'** 패턴으로 **좌표를 props 로 받는 전용 정적 렌더러**를 새로 쓴다. 좌표는 `model/playback.ts` 의 `RenderFrame`(절대 x/y/theta, :44-52)에서 얻는다 — §6.1 규칙 1 때문에 React 출력에 transform 이 없기 때문이다.
3. **한글은 SVG 에 넣지 않는다** ★ 안 2 이식 — 안 1·3 의 '조건부 폰트 인라인'을 이걸로 **교체한다**.
   - SVG 에 인라인하는 폰트: **Space Grotesk latin, base64 29,720 B 하나뿐**(등번호·격자 라벨).
   - 한글(제목·스텝 이름·메모)은 SVG 를 캔버스에 그린 **뒤** `canvas.fillText` 로 얹는다. 캔버스는 **문서 컨텍스트**라 이미 로드된 Pretendard 를 그대로 쓴다.
   - 회피하는 비용: `Pretendard-Regular` base64 **1,021,192 B**. 현재 dist 4.2 MB 중 3.9 MB 가 이미 폰트인 상황에서 런타임에 1 MB base64 를 만드는 것 자체가 잘못된 선택이고, 이 방법은 **조건 분기까지 없앤다.**
   - 메모는 코트 좌표이므로 `worldToClient` 로 위치를 계산해 얹는다.
4. **[A-9 정정] 등번호도 `fillText` 로 얹는다 — SVG 폰트 인라인을 아예 없앤다.** img 컨텍스트 안 SVG 의 `@font-face` 로드는 비동기라, `img.onload` 직후 `drawImage` 해도 **폰트가 안 실린 채 래스터되는** 형태가 알려져 있다. 원안은 한글만 `fillText` 로 빼서 그 위험을 등번호(Space Grotesk)에 그대로 남겼는데, **등번호가 빠진 PNG 가 나와도 코치는 그게 실패인지 모른다.** jsdom 에서 반증할 수 없는 구간이므로 설계로 위험을 없앤다 — 텍스트는 전부 캔버스에서 그리고, SVG 에는 도형만 남긴다. 그러면 Space Grotesk base64 29,720 B 인라인도 불필요해진다.
5. **[A-10 정정] 출력 배율을 명시한다.** viewBox 만 있고 `width`/`height` 가 없는 SVG 는 `<img>` 에서 내재 크기가 불확정이다. 확정: 직렬화 시 `width`/`height` 를 명시하고 **목표 긴 변 2048 px(약 2.5 px/월드px)** 로 굽는다. 인쇄물로 옮기는 것이 목적이므로 화면 devicePixelRatio 가 아니라 **출력 해상도**를 기준으로 잡는다.
6. taint 위험 없음 — `foreignObject` 0건, 외부 이미지 참조 0건(grep 확인).
5. **검증 경계**: jsdom 에 canvas 가 없다. 그러므로 **'SVG 문자열 생성'을 순수 함수로 물리적으로 분리**하고 가드를 그쪽에 몰아준다 — `class=` 잔존 0 · `var(--` 잔존 0 · `focus-ind` 잔존 0 · **U+00FF 초과 코드포인트 잔존 0**[A-8 정정: 원안은 '한글 코드포인트 0' 이었다. `fonts.css:43-61` 의 Space Grotesk latin 서브셋은 U+0000-00FF 뿐이라, 한글이 아니어도 U+0100 이상(예: 확장 라틴)이 들어가면 글리프가 빈다. 다만 A-9 정정으로 텍스트를 전부 캔버스로 옮기면 이 가드는 '텍스트 노드 잔존 0' 으로 더 강해진다] · `<text>` 노드 잔존 0. 래스터 어댑터(Image→canvas→toBlob)는 얇게 격리한다.

### 6.3 PDF — **`window.print()` + `@media print` 하나로 못박는다**

**세 경로를 비교하고 하나만 남긴다.**

| 경로 | 판정 |
|---|---|
| ㉠ jspdf / pdf-lib | **배제.** 저장소에 TTF/OTF 가 **0개**고 woff2 만 있다(find 확인). jsPDF 는 TTF 를 요구하고 pdf-lib+fontkit 도 woff2 를 직접 못 먹는다(브로틀리 디코더가 또 필요). 한글 벡터 텍스트를 넣으려면 **새 폰트 자산 수 MB 추가** — dist 4.2 MB 중 3.9 MB 가 이미 폰트다. 런타임 deps 3개 정책과도 충돌. |
| ㉡ **`window.print()` + `@media print`** | **채택.** 의존성 0 · 바이트 0 · 완전 오프라인. 결정적으로 **문서 컨텍스트에서 인쇄되므로 `fonts.css` 의 Pretendard 가 그대로 먹어 한글이 문제없다**(PNG 와의 비대칭). 코트 SVG 는 벡터로 인쇄된다. 반증 가능성이 가장 높다 — 인쇄용 React 트리는 jsdom 에서 스텝 수·순서·페이지 분할 마크업을 그대로 검증할 수 있고, 검증 불가 영역이 CSS 로만 좁혀진다. |
| ㉢ 서버 렌더 | **배제.** `REQUIREMENTS.md:19` '로컬 전용, 서버 없음'과 정면충돌. |

**문서 2종**

- **세션 계획서**: 표지 1장(세션명 · 날짜 · 장소 · 총 시간 · 드릴 순서 타임테이블) + 드릴마다 1장(코트 그림 · 배정 시간 · 스텝별 코칭 메모 · 다음 휴식).
- **드릴 시트**: 1페이지 = 1스텝(코트 그림 크게 + 스텝 이름 + 코칭 메모 + n/N + 그 스텝 소요 시간). 60스텝까지 페이지 분할.
- 머리글의 **준비물은 판에서 파생한다**(안 3 이식): 선수 n명 · 공 n개 · 콘 n개. **모델 확장 0 · validate 화이트리스트 0 · 요약 재생성 0** — 이미 있는 데이터만으로 훈련 계획서의 가장 실용적인 줄이 생긴다. 새 필드를 만들지 않는다.
- **[A-1 정정] 파생원이 개체 종류마다 다르다.** `cast` 를 쓰면 안 된다 — `defaultCast()` 는 courtMode 와 무관하게 **항상 양팀 8대**를 만들고(defaults.ts:25-33), `pruneOrphanCast` 는 휠체어를 제외하므로, 하프 코트(홈 GK 없음, 실제 6대)에서도 **어떤 드릴이든 "선수 8명"** 이 찍힌다. 확정: **선수는 전 스텝 pose 키의 합집합**에서, **공·콘은 `cast`** 에서(이쪽은 `pruneOrphanCast` 덕에 정확하다).

**필수 디테일 두 가지**

1. `print-color-adjust: exact` 가 없으면 초록 코트(`#1f7a46`)가 **흰색으로 인쇄된다.**
2. **[A-11 정정 — 이게 없으면 인쇄 자체가 성립하지 않는다]** `appShell.css:10-27` 이 `html, body, #root { height:100%; overflow:hidden }` 을 못박고 `#root` 에 safe-area 패딩을 준다. **이 상태로 `window.print()` 하면 60스텝이 1페이지로 잘린다.** 인쇄 스타일시트가 이 셋(`height`·`overflow`·safe-area 패딩)을 전부 해제하는 것이 6.3 의 **1순위 완료 판정**이다.

**보험 조항**: 인쇄 대화상자에서 '대상: PDF로 저장'을 고르는 정밀 조작(iPad 는 공유→인쇄→핀치→파일에 저장으로 더 길다)이 **실기에서** 실제 부담으로 판명되면, 6.2 의 PNG 렌더러를 그대로 재사용해 스텝마다 캔버스 1장 → `addImage` 하는 ㉠ 변형으로 승격한다. 이 변형은 텍스트를 래스터에 굽기 때문에 **폰트 임베드가 아예 필요 없고**, 그래서 ㉠ 의 유일한 치명상을 우회한다. → **PNG 를 먼저 만드는 것이 PDF 의 보험이다. 순서가 중요하다.**

### 6.4 진입점 — 형식을 묻되, 큰 표적 3개로만 묻는다

- **[보드] 하단 바에 [내보내기] 1개 → 큰 항목 3개 시트(인쇄 / 그림 / 파일).** 헤더가 아니라 하단 바인 이유는 narrow 헤더를 52px 한 줄로 강제하기 때문이다(5.2).
- **판 걸이 카드**: [공유] 1개(= PNG, 코치가 실제로 하는 행위) + ⋯ 3항목(복제 / 파일로 내보내기 / 삭제).
- **케밥에 PNG·PDF 를 얹지 않는다** — `DrillCard.tsx:157-172` 는 이미 2단계 정밀 조작이고, 여기에 3~4항목을 더하면 발 마우스 사용자에게는 기능 추가가 아니라 **결함 추가**다. 큰 타깃 3개가 작은 타깃 1개보다 싸다.

**추천: (B).** 근거는 `durationMin` 하나로 *"3회 × 2세트"* 를 표현할 수 없다는 것 — 세션 계획서의 실용성이 정확히 거기서 갈린다. 그리고 실제 계획서는 "3번"이 아니라 **이름**으로 읽힌다.

### ⑥ seed 드릴 3개의 실제 내용
3.5 가 여기서 막힌다. **앱 사용법을 시연으로 가르치는 유일한 장치**이므로(§3, `step.note` 가 시연 화면에서 크게 읽힌다) 콘텐츠가 곧 온보딩 대본이다.
- 필요한 것: 초급 1 · 중급 1 · 고급 1. 각 드릴의 **스텝별 `note` 문장**이 (a) 훈련 내용과 (b) 조작 설명을 동시에 담아야 한다. 예: 초급 1스텝 note = *"트레이에서 선수를 끌어다 놓습니다. 뒤 절반을 잡으면 그대로 밀리고, 앞 절반을 잡으면 제자리에서 돕니다."*
- **추천**: 기현님이 실제로 쓰는 드릴 3개의 제목·카테고리·스텝 구성을 주시면, 조작 설명 문장은 이쪽에서 현행 규칙(2026-08-11 트레이 재편 · 4존 운동학)과 대조해 채워 넣는다.
**⚠ 이건 3.8 의 게이트다** — 원안은 ② 만 "선행 조건"으로 표시했는데(E-8), ⑥ 도 똑같이 막는다.
