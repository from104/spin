# SPIN 요구사항 (확정본)

**SPIN** = *Strategy Planner for INclusive football*
파워체어 풋볼(전동휠체어 축구) 4v4 전술 보드 / 드릴 플래너.

원본 프로토타입: `docs/prototype/` (template.html = UI 마크업, logic.js = 상태·데이터).
프로토타입은 **순수 목업**이다 — 편집기 도구는 아이콘만 있고 동작하지 않으며,
드릴 6개·스텝 3개가 하드코딩되어 있고 저장/내보내기가 없다.
이 저장소의 목표는 그 컨셉을 **실제 동작하는 앱**으로 만드는 것이다.

---

## 1. 확정된 기술 결정

| 항목 | 결정 |
|---|---|
| 스택 | **React 19 + Vite + TypeScript** |
| 물리 | **matter.js** (2D 게임 물리 엔진) — 코트 위 모든 개체 |
| 저장 | **로컬 전용, 서버 없음**. IndexedDB(`idb`) + 드릴별 JSON 파일 내보내기/가져오기 |
| 렌더 | **SVG** (프로토타입과 동일). matter.js는 headless 물리로만 사용 |
| 배포 | 정적 빌드. 체육관 오프라인 사용 가정 (폰트·에셋 전부 번들 내장) |

## 2. 1차 버전 필수 범위

1. **편집기 실제 동작** — 코트 위 드래그 조작, 스텝 추가·복제·삭제
2. **드릴 CRUD + 라이브러리** — 생성·저장·복제·삭제, 카테고리 필터, 검색, 카드 썸네일 자동 생성
3. **시연 모드** — 전체화면, 큰 버튼, 화면 꺼짐 방지(Wake Lock), 스와이프 스텝 이동
4. **훈련 세션** — 드릴 여러 개를 순서대로 묶어 총 시간 계산, 세션 단위 시연

## 3. 코트 규격

프로토타입 좌표계를 유지한다. **월드 단위 = 미터**, 렌더 스케일 25 px/m.

| 모드 | 실제 규격 | viewBox | 경기면(SVG 좌표) |
|---|---|---|---|
| `full` 풀 코트 | 30 × 18 m | `0 0 800 500` | x 25..775, y 25..475 (750 × 450) |
| `half` 하프 코트 | 18 × 15 m, 90° 회전 | `0 0 500 425` | x 25..475, y 25..400 (450 × 375) |
| `flat` 플랫 코트 | 라인 없음 | `0 0 500 425` | 자유 배치 |

파워체어 풋볼 규칙 요소(프로토타입에 이미 있음, 유지):
- 골 지역 **2인 규칙** 존 하이라이트 (토글)
- 골포스트, 코너 컷, 킥인 마크

## 4. 물리 · 조작 요구사항 (핵심)

### 4.1 개체

| 개체 | 수량 | 비고 |
|---|---|---|
| 휠체어(선수) | 양팀 각 4 (GK 포함) | 아래 운동학 적용 |
| 공 | **최대 10개** | 편집기에서 추가·삭제 |
| 훈련 콘 | 제한 없음, **2가지 색** | 편집기에서 배치 |

### 4.2 휠체어 회전축

- 회전축은 **차체 뒤 중앙에서 전체 길이의 1/5 지점** (= 탑승자 머리 위치).
- 즉 차체를 뒤(s=0) → 앞범퍼(s=L)로 볼 때 **피벗은 s = 0.2·L**.
- matter.js에서는 `Matter.Body.setCentre(body, offset, true)`로 회전 중심을 옮긴다.

### 4.3 드래그 4존 (차체 길이 방향 기준)

잡은 지점이 차체 어디냐에 따라 조작 방식이 달라진다.

| 존 | 위치 | 동작 |
|---|---|---|
| **후방 견인** | 피벗보다 뒤 | 뒤에 줄을 매달고 끌려가듯. 차체가 진행 방향을 따라 **자연스럽게 방향 전환**하며 후진 |
| **평행 이동** | 피벗(머리) 부근 | **방향 전환 없이** 그대로 평행 이동 |
| **제자리 회전** | 머리 ~ 앞범퍼 사이 | 피벗 고정, 축을 중심으로 **제자리 회전** |
| **전방 견인** | 앞범퍼 | 앞에 줄을 매달고 끌고 가듯. **자연스럽게 방향 전환**하며 전진 |

견인(tow) 동작은 로프/트레일러 운동학으로 구현한다: 잡은 점이 포인터를 추종하고,
피벗은 잡은 점으로부터 고정 거리를 유지하며 끌려온다. 차체 방향은 그 벡터에 정렬된다.

존 경계값은 **설정에서 조정 가능**해야 한다 (기본값은 설계 단계에서 확정).

### 4.4 속도 상한

- 전후진: **10 km/h** (= 2.778 m/s)
- 회전: **앞범퍼의 좌우 이동 속도 기준 30 km/h** (= 8.333 m/s)
  → 각속도 = 8.333 / (앞범퍼 ~ 피벗 거리). 조정 가능한 설정으로 노출할 것.

드래그 시 포인터가 아무리 빨라도 이 상한을 넘지 않게 프레임당 변위를 클램프한다.

### 4.5 충돌

휠체어끼리, 휠체어↔공, 휠체어↔콘 충돌이 물리적으로 자연스러워야 한다.
휠체어는 질량이 커서 공·콘을 밀어내고, 공·콘에 밀려나지 않는다.

## 5. 격자 오버레이 (토글 옵션)

실선 격자 + 칸 번호를 **흐릿하게** 표시. 열=알파벳, 행=숫자 (`a1`, `b4` …).

| 모드 | 격자 |
|---|---|
| `full` 풀 코트 | 가로 **6** × 세로 **5** 칸 (칸 크기 5 m × 3.6 m) |
| `half` 하프 코트 | 90° 회전 기준 가로 **5** × 세로 **3** 칸 (칸 크기 3.6 m × 5 m) |
| `flat` 플랫 코트 | **1 m 간격** 실선 격자 |

## 6. 저장

- **드릴 하나하나 따로** 저장·불러오기. 서버 없음.
- IndexedDB에 보관 + 개별 드릴을 `.json` 파일로 내보내기/가져오기.
- **추후 예정** (1차 범위 아님, 데이터 구조에 여지만 남길 것):
  - 드릴 셋(여러 드릴 묶음) 기능
  - 설정 내보내기
