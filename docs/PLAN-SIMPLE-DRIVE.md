## A. 심플 모드

### 결정 A1 — 무엇인가
휠체어를 **원**으로 그리는 보기 모드. 켜져 있는 동안 **물리 상호작용은 원천적으로 없다**:
개체끼리 밀지도 막히지도 않고 겹쳐 지나간다. 끌기 회전·견인 존·앞뒤 앵커도 없다(차체 개념이 없으므로).

- 모델(드릴 데이터)은 **바뀌지 않는다** — 자세(x, y, angleDeg)는 그대로 저장된다. 심플 모드를 껐다 켜도 같은 판이다.
- 스키마 번호를 올리지 않는다(드릴 v11 그대로). 설정만 늘어난다(prefs).

### 결정 A2 — 어디에 저장하나 ⚑
**기기 설정**(prefs.physics 옆, `prefs.board.simple: boolean`, 기본 끔). [보드 설정] 모달 맨 위 스위치 [심플 모드].
- 근거: [물리·상호작용]·[끌어 회전하기]·[앞뒤 앵커]가 이미 기기 설정이고 같은 모달에 산다. 드릴마다 저장하면
  "같은 드릴이 기기마다 다르게 보인다"는 혼란 대신 "공유받은 드릴이 내 설정과 다르게 열린다"는 혼란이 생긴다.
- 대안(드릴별 저장)은 공유 링크·시연에서 작성자 의도를 지키는 장점이 있다 — 나중에 필요하면 드릴 필드로 옮긴다.

### 결정 A3 — 어디까지 원으로 그리나 ⚑
**모든 표시 경로**가 같은 설정을 따른다 — "보이는 것 = 내보내지는 것".

| 경로 | 파일 | 할 일 |
|---|---|---|
| 편집 화면 | `render/objects/ChairChip.tsx` (ObjectLayer) | 원 갈래 추가 |
| 시연 | `features/present/PresentObjects.tsx` → ChairChip | ChairChip 공유로 자동 |
| 트레이 미리보기 | `features/editor/TrayGhost.tsx` | 원 갈래 |
| 목록 썸네일 | `render/CourtThumbnail.tsx` | 원 갈래 |
| 내보내기 PNG·MP4 | `features/export/buildStaticSvg.ts`·`staticSceneLayout.ts` | 원 갈래 |
| 인쇄 | `features/print/PrintCourt.tsx` | 원 갈래 |
| 선택 테두리·잠금 표시 | `render/objects/LockTint.tsx`, 선택 오버레이 | 원 모양 |
| 앵커·존 커서 | `render/ZoneHandles.tsx`, `render/zoneCursors.ts` | 심플 모드에서는 안 그림 |
| 규칙 화면 그림 | 규칙 장면은 **늘 실물 차체**(규칙 설명이 차체 크기에 걸려 있다) | 손대지 않음 |

⚠️ 일곱 갈래에 원을 따로 그리면 반드시 한쪽이 어긋난다 — **원 하나의 기하를 한 곳에**(`model/chairDisc.ts`: 지름·번호
글자 크기·방향 표시 위치) 두고 모든 경로가 거기서 읽는다(트레이 고스트 사고 72a6a12 와 같은 교훈).

### 결정 A4 — 원의 모양 ⚑
- **지름 1.0 m**(25 px). 차체 1.3 × 0.8 m 사이 값 — 포메이션 간격이 실물 판과 비슷하게 읽힌다.
- 팀 색 채움 + 흰 테두리(지금 칩과 같은 색 규칙 `inkFor`), 등번호 가운데. 골키퍼 표시는 지금과 같은 규칙.
- **방향 눈금**: 원 둘레에 보는 쪽으로 작은 삼각 눈금 하나. ⚑ 기현님 답("표시만 원으로")이 방향 표시 유무를
  말하지 않았다 — 기본값은 **눈금 있음**. 근거: 주행 모드(B)·방향판·숫자키 1–9 가 모두 "보는 쪽"을 쓴다.
  눈금이 없으면 심플 모드에서 주행할 때 어느 쪽이 앞인지 안 보인다.
- **원의 중심 = 피벗(pose x, y)** (2026-11-16 기현 보강). 몸통 중심(피벗 + 9.75 px)이 아니다 — 원이 제자리에서 돌아야 하므로
  Q/E·방향판에서 원이 피벗 둘레를 공전하면 안 된다. 방향 눈금은 heading 쪽 원 둘레.
- **벽 경계 클램프는 원(반지름 12.5 px) 기준** (같은 보강). 실물 차체 기준이면 앞벽 0.54 m 못 미쳐 멈추고 뒤로는 6 px 삐져나간다.
  심플 모드를 끄면 차체 기준으로 돌아간다 — 저장 데이터는 건드리지 않는다(`Bounds.disc`, `world.setDiscBounds`).

### 결정 A5 — 물리 상호작용 없음의 구현
- 심플 모드가 켜지면 `world.setInteract(false)` 를 **강제**한다(EditorProvider 의 physics effect 에서
  `interact && !simple`). [물리·상호작용] 스위치는 꺼진 채 비활성 + "심플 모드에서는 쓸 수 없습니다" 안내.
- [끌어 회전하기]·[앞뒤 앵커 보이기]도 비활성(원에는 견인 존이 없다). 저장값은 건드리지 않는다 — 심플 모드를 끄면 원래대로.
- 끌기: 원은 **어디를 잡아도 평행 이동**(지금 dragRotate 끔과 같은 길). 회전은 Q·E·방향판·숫자키로만.
- 키보드·패드 이동은 sweepTo 가 false(상호작용 끔)를 돌려주므로 순간이동 — 0.6.14 그대로.
- 판 밖으로 나가지 않게 하는 **벽 경계는 남긴다**(상호작용 끔에서도 지금 escapePinnedAll 이 경계만 지킨다).
- 히트 판정: 원(지름 1.0 m + 큰 터치 타깃이면 기존 패딩) — `physics/hitTest.ts` 에 원 갈래.

### 결정 A6 — 시연·내보내기의 물리
시연은 물리를 돌리지 않는다(트윈) — 원 그림만 바뀐다. 영상(MP4)은 같은 원 기하로 프레임을 그린다.

## B. 주행 모드

### 결정 B1 — 무엇인가
고른 **휠체어 한 대**를 실제 파워체어처럼 조종해 판 위를 다니게 하는 편집 모드. 결과는 **지금 스텝의 자세만 바뀐다**
(Q4). 편집기·전술판 둘 다. 시연 화면에는 없다. **심플 모드에서는 주행 모드가 없다**(Q5) — 메뉴·기능바·`G` 모두 비활성
+ "심플 모드에서는 쓸 수 없습니다" 안내. 주행 중 심플 모드를 켜면 주행을 먼저 끝낸다(커밋 후 전환).

### 결정 B2 — 들어가고 나오기
- 들어가기: 휠체어를 고른 뒤 ① 개체 메뉴 [주행], ② 기능바 [주행] 단추(휠체어 하나가 골라져 있을 때만 활성),
  ③ 키 `G`(전역 단일 문자키 — WCAG 2.1.4 게이트(`singleKeyShortcuts`)를 탄다). ⚑ 키 글자는 도구 키와 안 겹치는 것 중 하나.
- 주행 중 다른 휠체어를 누르면 **그 휠체어로 갈아탄다**(모드 유지).
- 나오기: `Esc`, [주행 끝] 단추, 다른 도구를 고름, 스텝 전환·재생 시작. 나올 때 정착을 기다려 커밋(결정 B7).
- 잠긴 휠체어·무시한 휠체어는 주행할 수 없다(메뉴 비활성, 안내).

### 결정 B3 — 조종 모델 (실제 파워체어식, Q2)
차동 구동 하나로 정리한다. 입력은 두 축 `fwd ∈ [-1, 1]`(위 +), `turn ∈ [-1, 1]`(오른쪽 +).

```
v  = fwd  × Vmax(단계)              // 보는 쪽(heading) 선속도, 뒤로 가면 음수
ω  = turn × Ωmax(단계)              // 제자리 회전 각속도(시계 +)
후진 중 좌우 회전 방향은 **조이스틱을 민 쪽으로 차 뒤가 돈다**(실제 컨트롤러 관례) ⚑
매 프레임: θ += ω·dt,  p += v·dt·(cos θ, sin θ)
```
- **피벗**은 지금 휠체어 자세의 x,y(뒷바퀴 축, `CHAIR.pivotToRearPx` 6.5 px 뒤가 차체 끝) — 제자리 회전이 실물처럼 뒤쪽 축 중심.
- 가속: 0 → 목표 속도까지 **0.3 s** 선형 램프, 손을 떼면 0.2 s 에 정지(급정거 튐 방지). ⚑
- 데드존: 스틱 반경의 12%.

### 결정 B4 — 속도 5단계 ⚑
FIPFA 상한 10 km/h 를 5단계로 나눈다. 회전은 단계에 비례(실측 파워체어 감각: 최고 단계에서 반 바퀴 ≈ 1.5 s).

| 단계 | 선속도 | px/s(25 px/m) | 제자리 회전 |
|---|---|---|---|
| 1 | 2 km/h | 13.9 | 24 °/s |
| 2 | 4 km/h | 27.8 | 48 °/s |
| 3 (기본) | 6 km/h | 41.7 | 72 °/s |
| 4 | 8 km/h | 55.6 | 96 °/s |
| 5 | 10 km/h | 69.4 | 120 °/s |

- 단계는 기기 설정(`prefs.drive.speed`, 기본 3)에 남는다 — 다음에 들어가도 같은 단계.
- 상수는 `core/constants.ts` 에 `DRIVE` 로 한 곳(PX_PER_M 은 기존 값에서 유도, 숫자를 베끼지 않는다).

### 결정 B5 — 입력 (Q3)
**화면 가상 조이스틱**
- 판 오른쪽 아래(왼손잡이 설정은 ⚑ 다음 단계)에 반투명 원판 + 손잡이. 지름 140 CSS px(큰 터치 타깃이면 180).
  **UI 배율 래퍼 밖으로 포털**(72a6a12 교훈 — `.spin-scale` 안의 fixed 는 어긋난다).
- 손잡이를 끌면 위아래 = fwd, 좌우 = turn(화면 축 그대로 — 차가 돌아가 있어도 "위 = 앞으로", 실제 조이스틱과 같다).
  놓으면 가운데로 돌아가며 정지.
- 조이스틱 옆에 속도 단계 버튼 [−] [3] [+] (또는 1–5 다섯 칸) ⚑.
- 포인터 캡처로 판 끌기·선택과 섞이지 않는다. 멀티터치: 조이스틱 손가락 하나만 받는다.

**키보드**
- 주행 중에는 새 스코프 `drive` 가 개체 스코프보다 먼저 키를 먹는다:
  `W`/`↑` 전진, `S`/`↓` 후진, `A`/`←` 왼쪽 회전, `D`/`→` 오른쪽 회전(동시 누름 = 호를 그리며 주행).
  키는 누르는 동안 1, 뗄 때 0 — 램프(B3)로 부드럽게.
- 속도 단계: `1`–`5` ⚑ — 주행 중에만 숫자키가 속도로 바뀐다(평소 `obj.face` 1–9 는 주행 중 꺼짐).
  다른 안: `-`/`=`. 결정은 keymap contract 시험과 함께.
- `Esc` 주행 끝.
- keymap.ts 에 `drive.*` 정의 → 도움말 단축키 표 자동, keymapDesc en/ja 번역, keymap.contract 의 겹침 규칙에 스코프 추가.

### 결정 B6 — 물리와의 관계
- **주행 중 물리 상호작용은 강제 켬**(Q5): EditorProvider physics effect 의 실효값을
  `(interactPref || driving) && !simple`. [물리·상호작용] 저장값은 건드리지 않고, 주행이 끝나면 원래 값으로 돌아간다.
  주행 중 그 스위치는 켜진 채 비활성 + "주행 중에는 항상 켜짐" 안내.
- 매 프레임 다음 자세를 계산하고 **`sweepTo([{id, pose}], dt)`** 로 옮긴다(0.6.14 에서 만든 길 그대로) —
  공·콘·휠체어를 실제 빠르기로 민다. 주행 중엔 상호작용이 늘 켜져 있으므로 `setPose` 순간이동 갈래는 쓰지 않는다.
- 주행하는 휠체어는 손의 권위(static) — 남에게 밀려 되돌아가지 않는다. 벽은 막는다
  (sweepTo 의 걸음마다 `pushChairIntoBounds` 를 거친다 — **지금 sweepTo 에는 벽 막기가 없다 → 구현 항목**).
- **잠긴 개체: 부딪혀 막힌다**(움직이지 않는 벽처럼 — 드래그의 lockedBlockers 와 같은 규칙).
- **무시한 개체(`ignored`): 통과한다** — 주행 휠체어와 충돌하지 않고, 밀리지도 않는다. 숨긴 개체도 같다(물리에 없다).
  구현 전 확인: 지금 물리 세계가 ignored 개체를 몸체로 갖는지 → 갖는다면 주행 중 그 몸체의 충돌 필터를 끈다.
- 강제 켬의 위험(3단계에서 확인): 상호작용 끔 상태에서 이미 겹쳐 있던 개체들이 주행 시작 순간 서로 튕겨 나갈 수 있다.
  → 주행 시작 시 **주행 휠체어와 닿는 쌍만** 반응하게 하거나, 겹친 쌍은 떨어질 때까지 충돌을 미룬다. 기본은 후자.

### 결정 B7 — 기록·되돌리기 (Q4)
- 주행 **한 번(들어가서 나올 때까지)** = 되돌리기 한 칸. 첫 움직임에서 `PLACE_BEGIN`, 주행 중 0.5 s 마다·멈출 때
  `PLACE_COMMIT`(past 불변, present 갱신 — 자동저장 억제 창은 드래그와 같은 `SETTLE_ARM`), 나올 때 정착 뒤 `PLACE_SETTLE`.
- 밀린 이웃도 같은 칸에 들어간다(stepPosesFromSnapshot — 0.6.14 공용 함수).
- 스텝 전환·재생·다른 드릴 열기는 주행을 먼저 끝낸다.

### 결정 B8 — 화면 표시
- 주행 중인 휠체어에 테두리 강조 + 앞쪽 짧은 진행 방향 화살표. 상단 띠: "주행 중 · 속도 3 · Esc 로 끝".
- 스크린리더: 들어갈 때·속도 바꿀 때·나올 때 한 줄 발표(LiveRegion, useThrottledAnnounce).
- 감축 모션: 램프만 짧게(0.1 s) — 움직임 자체는 사용자가 만드는 것이라 끄지 않는다.

## C. 공통 · 품질

### C1 — 문구·도움말 (ko/en/ja)
- i18n: [심플 모드] 스위치·안내, [주행]·[주행 끝]·속도 단계·발표 문구, 비활성 이유.
- 도움말(`helpContent.*`): [보드 설정] 주제에 심플 모드, 새 주제 "주행 모드"(조이스틱·키·속도·되돌리기).
  주제 id 를 늘리면 `docs/PLAN-HELP-OVERHAUL.md` §2.1 과 세 파일을 같은 커밋에서(계약 시험).
- 튜토리얼: 이번에는 손대지 않음 ⚑(둘러보기 한 칸 추가는 다음).
- CHANGELOG 세 벌 [Unreleased] 추가됨.

### C2 — 시험 (값 있는 것만, 새 단언은 돌연변이로 확인)
- 단위: `chairDisc` 기하 한 곳 / 심플 모드에서 `setInteract(false)` 강제 / 주행 운동학(B3 식 — 전진·후진·회전·호,
  램프·데드존) / 속도 단계 표 / sweepTo 벽 막기.
- e2e 웹(4 프로젝트): **S18 심플 모드** — 켜면 휠체어가 원(`data-shape="disc"`), 상호작용 스위치 비활성, 끌어 겹쳐도
  안 밀림, 내보내기 SVG 에도 원. **S19 주행(키보드)** — W 를 0.5 s 누르면 보는 쪽으로 이동·거리 ∝ 속도 단계,
  A 로 회전, Esc 로 나와 되돌리기 한 번에 원위치. **S19b 주행(조이스틱, touch 프로젝트)** — 손잡이를 위로 끌면 전진.
  세로 창(코트가 돈 휴대폰)에서 "위 = 보는 쪽"이 화면과 무관함을 확인.
- 실앱(app 층): 공유 부분집합에 S19 만 추가 ⚑.
- 물리 상호작용 + 주행으로 공 밀기는 S17b 와 같은 모양으로 한 단계.

### C3 — 단계(커밋 묶음)
1. **심플 모드 바탕**: prefs 필드·[보드 설정] 스위치·`chairDisc`·ChairChip/TrayGhost 원 갈래·상호작용 강제 끔·히트 판정.
2. **심플 모드 나머지 경로**: 썸네일·내보내기·인쇄·선택/잠금 표시·앵커 숨김 + S18.
3. **주행 엔진**: 운동학·램프·속도 표·sweepTo 벽 막기·주행 세션(들어가기/나오기/되돌리기) + 단위 시험.
4. **주행 입력**: 키보드 스코프 `drive` + keymap 계약 + S19.
5. **가상 조이스틱**: 포털·포인터 캡처·속도 단추·큰 타깃 + S19b.
6. **문구·도움말·CHANGELOG** 세 벌 + 실기 확인(개발 서버·AppImage·안드로이드 태블릿).

각 단계는 lint 기준선 48 유지, `npm run typecheck`, 해당 e2e 4 프로젝트 초록에서 끝난다. 구현은 opus(어려운 3·5) /
sonnet(1·2·4·6), 검증은 한 단계 위 모델(AGENTS.md §10).

### C4 — 다음 단계로 미룬 것
- 주행 경로 녹화 → 스텝·경로 화살표 생성(Q4 의 2단계).
- 실물 게임패드(Gamepad API).
- 왼손잡이 조이스틱 위치, 튜토리얼 칸.
- 심플 모드를 드릴별로 저장(공유 링크에서 작성자 보기 지키기).
