## A. 전역 [도움말] — 레일 일원화

- 왼쪽 레일(AppNav): 테마 토글 **위**에 [도움말] 버튼. 좁은 창(레일 접힘)에서는
  AppNavAside(헤더 오른쪽 끝, 테마·버전 묶음)에 함께 들어간다 — "접는 것이지 재배치가
  아니다" 관례 그대로.
- 편집 FunctionBar 의 [도움말] 칸 제거 → `FUNCTION_BAR_ITEMS` 13→12, `_DRILL` 11→10.
  시연 PresentSideBar 의 [도움말] 제거 → 전체화면 1칸만 남는다.
  ⚠️ **크롬 예산 파급**: functionBarMetrics 상수와 chromeBudget.test.ts 실측값 재계산 필요
  ([저장] 칸 제거 때와 같은 절차 — 커밋 9ae60d8 참조).
- 단축키 Shift+? 는 유지하되 **전역 도움말**을 연다(keymap 재배선).
- 기존 HelpModal(편집 단축키 표)·HelpOverlay(시연 단축키 표)는 **은퇴** — 그 내용(단축키
  표)은 문서형 도움말의 화면별 섹션 안으로 흡수된다.

## B. 문서형 도움말 (HelpCenter)

- CenterModal 기반. 왼쪽 목차(화면별 섹션) + 오른쪽 본문 스크롤.
- **현재 화면에 맞는 섹션이 열린 채로 뜬다** — 편집에서 열면 "드릴 편집" 섹션부터.
- 섹션 구성: 시작하기 / 자유 전술판 / 드릴 목록 / 드릴 편집 / 세션 / 시연 / 설정·데이터 /
  단축키(화면별 표 — 옛 HelpModal·HelpOverlay 내용의 새 집).
- 각 섹션 끝에 [이 화면 투어 다시 보기] 버튼 — 튜토리얼 수동 재시작 진입점.
- 문구는 전부 i18n 키(`help.*`) — 3로케일 동시.

## C. 튜토리얼 엔진 (자체 구현)

**파일 구조**
- `src/ui/tutorial/TutorialOverlay.tsx` — 스포트라이트 오버레이(표시 전용)
- `src/ui/tutorial/useTutorial.ts` — 상태·진행·플래그 훅
- 단계 정의는 화면 곁에: `src/features/<화면>/tutorialSteps.ts`

**스포트라이트 기법**
- `position:fixed` 전체 덮개 + SVG `<path fill-rule="evenodd">` — 전체 사각형에서 대상
  사각형(둥근 모서리, 여백 몇 px)을 뺀 구멍. 어두운 부분만 `pointer-events` 를 받아
  대상 요소는 클릭 가능(단, v1 은 "보기만" — 다음 단계로는 버튼/키로만 진행).
- 대상 지정: 각 화면이 안내할 요소에 `data-tut="<id>"` 를 붙이고, 엔진이
  `getBoundingClientRect` 로 잰다. resize·화면 회전 시 재측정.
- 말풍선: 구멍의 상하좌우 중 공간이 남는 쪽에 자동 배치. 단계 n/N · 제목 · 설명 ·
  [이전][다음]([마지막이면 완료])·[건너뛰기]. 화살표(꼬리)가 구멍을 가리킨다.
- `prefers-reduced-motion`/prefs.reduceMotion 존중 — 구멍 이동 트랜지션 생략.

**접근성 (완전 대응)**
- `role="dialog" aria-modal="true"` + 포커스 트랩(ui/Modal 관용구 재사용).
- ←/→ 이전·다음, Enter 다음, Esc 종료(= 건너뛰기와 같음, 플래그는 찍는다 — 안 찍으면
  들어올 때마다 다시 시작돼 탈출이 탈출이 아니게 된다).
- 단계가 바뀔 때 liveRegion 으로 "n/N 제목 — 설명" 낭독.

**1회성 플래그**
- `prefs.tutorialsSeen: { library?: true; sessions?: true; editor?: true; board?: true; present?: true; sessionEditor?: true }`
  — 없음 = 안 봤음(스키마 확장 없이 키 생략 관례). 화면 첫 진입(마운트 + 데이터 준비 완료)
  시 자동 시작.
- 설정에 [도움말·튜토리얼] 행 신설: [튜토리얼 다시 보기] 버튼 = 플래그 전체 삭제.
- ⚠️ 시연 화면은 자동 전체화면(prefs.present.autoFullscreen)과 겹칠 수 있다 — 튜토리얼이
  뜨는 첫 방문에는 전체화면 자동 진입을 미루고, 튜토리얼 종료 후 진입.

**표적 예산**
- 오버레이·도움말 모달은 열려 있을 때만 DOM — 예산 밖.
- 레일 [도움말] +1 은 편집 기능바 [도움말] −1 과 상쇄(전술판 화면 기준). 목록·세션·설정
  화면은 +1 이지만 그 화면들의 예산 여유는 충분하다(게이트는 boardTargetBudget = 전술판).

## D. 화면별 튜토리얼 단계(안) — 문구는 구현 시 확정

| 화면 | 단계 | 내용(순서대로) |
|---|---|---|
| 드릴 목록 | 3 | [새 드릴] → 카드(열기·시연·더보기) → 필터·카드/목록 전환 |
| 세션 목록 | 2 | [새 세션] → 카드(열기·시연) |
| 자유 전술판 | 5 | 트레이(칩·공·콘) → 코트에 놓기 → 작도(화살표·도형) → 기능바(내보내기·보기) → [드릴로 저장] |
| 드릴 편집 | 8 | 스텝 사이드바 → 스텝 추가(+) → 트레이 → 코트 배치 → 재생 묶음 → 노트 → ⓘ 드릴 정보 → [시연으로] |
| 시연 | 4 | 재생 묶음 → 스텝 진행바 → 세로바(전체화면) → [편집으로]/Esc·스와이프 |
| 세션 편집 | 5 | 세션 정보(메모·시간) → 구획 추가 → 드릴 편성 → 배분 게이지 → 참가자 체크 |

## E. 구현 순서 (한번에 전부, 순차 커밋)

1. **엔진** — TutorialOverlay + useTutorial + prefs.tutorialsSeen + 단위 테스트
2. **드릴 편집 튜토리얼**(가장 복잡, 8단계) — 엔진의 실기 검증대
3. **나머지 5개 화면** 튜토리얼 (화면당 1커밋 또는 묶음)
4. **HelpCenter**(문서형 도움말) + 콘텐츠 3로케일 + 단축키 표 흡수
5. **레일 [도움말] + 기능바/세로바 칸 제거** + 예산 재계산 + HelpModal/HelpOverlay 은퇴 + Shift+? 재배선
6. **설정 리셋 버튼** + CHANGELOG/ROADMAP 갱신

## 위험

- **예산표 파급** — 기능바 칸 수 변경은 열 수 계산→코트 상자 폭→회전 판정까지 흐른다.
  9ae60d8 이 간 길을 그대로 따른다(items·dividers 상수, chromeBudget.test 실측 갱신).
- **jsdom 이 못 재는 것** — getBoundingClientRect 가 jsdom 에서 0 이라 스포트라이트 좌표는
  단위 테스트로 못 박는다. 계약(플래그·진행·접근성 속성·낭독)만 jsdom, 시각은 실기.
- **첫 방문 자동 시작 × 데이터 로딩** — 목록이 비었을 때(빈 상태 화면)는 안내할 대상이
  없다. 빈 상태에서는 대상이 존재하는 단계만 걸러서 진행한다(전부 없으면 시작 안 함,
  플래그도 안 찍음).
