# SPIN 실기 검증 경로 (로드맵 0.5) — FIELD-TEST

> **이 문서의 존재 자체가 0.5 의 완료 판정 절반이다.** 나머지 절반은 기기 매트릭스(§2)의
> 최소 요건 행이 채워지는 것이다. 4.3(iPad revoke/share) · 4.5(인쇄 품질) ·
> 2.3(가로/세로 실면적)의 완료 판정은 전부 "실기 확인"인데, jsdom 은 `navigator.share`
> 도 인쇄도 no-op 이라 **실기 외에는 반증 경로가 없다** (`docs/PLAN-2026-08.md` §6.1d ·
> §6.3 보험 조항 · §5.2 A-12).
>
> 이 체크리스트는 "화면이 예쁜가"를 묻지 않는다. 주 사용자는 뇌병변 사지마비 코치다 —
> 마우스는 오른발, 타이핑은 입에 문 젓가락. 모든 항목은 **"발과 젓가락으로 이 조작이
> 되는가"** 를 참/거짓이 갈리는 문장으로 묻는다. "자연스러운가" 같은 판정 불가 문장은
> 이 문서에 넣지 않는다 — 넣으려던 사람이 참/거짓 문장으로 고쳐 쓴다.

## 1. 접속 방법 — 태블릿에서 dev/preview 서버에 붙기

서버는 cube 에서 돈다. 설정 근거는 전부 `vite.config.ts` 의 주석에 있다
(host: true = 0.0.0.0 바인딩 · strictPort · allowedHosts).

### 1.1 서버 띄우기 (cube 에서)

```sh
npm run dev        # 개발 서버, 포트 5173
# 또는
npm run build && npm run preview   # 실기 판정용 프로덕션 빌드, 포트 4173
```

- **실기 판정은 preview(4173)로 한다.** dev 서버는 HMR·소스맵이 붙어 성능 특성이
  다르다 — 특히 4.5 인쇄 품질과 2.3 실면적의 최종 기록은 preview 기준이어야 한다.
- `strictPort: true` 라 포트가 잡혀 있으면 **밀려나지 않고 그냥 실패한다.** 실제 사고
  전례(vite.config.ts 주석): 두 번째 서버가 5174 로 밀려나 브라우저가 17시간 된 5173 을
  보고 있었다. 서버가 안 뜨면 낡은 서버부터 죽인다.

### 1.2 태블릿에서 붙기

| 상황 | 주소 | 근거 |
|---|---|---|
| 같은 LAN | `http://cube:5173` 또는 `http://cube.local:5173` | `allowedHosts: ['cube', 'cube.local']` |
| 테일스케일에 물린 기기 (어디서든) | `http://cube.tail4fa6d9.ts.net:5173` | `allowedHosts` 의 `'.ts.net'` — 앞 점은 하위 도메인 와일드카드 |
| 위 둘 다 안 될 때 | `http://<cube의 IP>:5173` | IP 직접 접속은 allowedHosts 검사 자체가 없다 |

- preview 는 위 주소의 포트만 `:4173` 으로 바꾼다.
- 호스트명 접속에서 **403 "Blocked request"** 가 뜨면 그 호스트명이 `allowedHosts` 에
  없는 것이다 — IP 로 우회하거나 `vite.config.ts` 를 고친다.
- **테일넷은 방화벽을 따로 열 필요가 없다** — ts-input 체인이 ufw 보다 앞에서
  tailscale0 인입을 전부 통과시킨다(vite.config.ts 주석 실측, 커밋 407a4cf).
- iPad 를 테일넷에 넣으려면 App Store 의 Tailscale 앱으로 같은 테일넷에 로그인한다.
  안드로이드도 동일. 훈련장처럼 LAN 이 없는 곳에서는 이 경로가 유일하다
  (태블릿에 LTE/테더링만 있어도 붙는다).

### 1.3 standalone(홈 화면 추가)으로 띄우기 — 4.3 검증의 전제

`index.html` 이 manifest + `apple-mobile-web-app-capable` + `black-translucent` 상태바를
이미 갖추고 있다(§6.4). **4.3 의 핵심 시나리오가 "standalone 에는 브라우저 크롬이 없어
다운로드 UI 가 보이지 않는다"이므로, iPad 검증은 반드시 두 모드를 다 돈다:**

1. **Safari 탭 모드**: 주소를 그냥 연다.
2. **standalone 모드**: Safari 공유 버튼 → "홈 화면에 추가" → 홈 화면 아이콘으로 실행.
   상태바 뒤까지 앱이 그려지고(safe-area 겹침), 이 겹침이 2.3 검증의 대상이기도 하다.

안드로이드는 Chrome 메뉴 → "홈 화면에 추가"(또는 "앱 설치").

## 2. 기기 매트릭스

### 2.1 최소 요건 (0.5 완료 판정)

| 요건 | 이유 | 확보 여부 |
|---|---|---|
| **안드로이드 태블릿 7~10인치 1대** | §5.3 실측표의 800×480(7인치)·1024×600(10인치) 행이 예측값이다 — 실물 없이는 예측으로만 남는다 | ☐ |
| **iPad 1대** | 4.3 의 `navigator.share`/revoke 는 jsdom no-op 이라 **실기 외 확인 경로가 없다.** safe-area(홈 인디케이터·노치)도 iPad 에만 있다(A-12) | ☐ |

### 2.2 §5.3 실측표 대조 (풀 코트 825×525, `pxPerUnit = min(boxW/825, boxH/525)`)

아래 수치는 계산 예측이다. 실기에서 상자 실측을 채워 예측이 맞는지 대조한다.
PC 행 둘은 이미 확보된 환경(gofu)이므로 참고로만 둔다.

| 기기 | 상자(예측) | pxPerUnit | 변화 | 1 m | 휠체어 잡기 hull | 확보 여부 | 실측 상자 |
|---|---|---|---|---|---|---|---|
| 1024×600 가로 (narrow) | 907×468 | 0.8914 | 0.6073 → +46.8% | 22.3 px | 51.3 × 40.1 | ☐ | |
| 800×480 (진짜 7인치) | 683×348 | 0.6629 | 0.3358 → +97.4% | 16.6 px | 38.1 × 29.8 | ☐ | |
| iPad (기종 미정 — 실측 없음) | **예측 불가** | — | — | — | — | ☐ | |
| 1280×800 PC (오버레이) | 1055×604 | 1.1505 | 0.9176 → +25.4% | 28.8 px | 66.2 × 51.8 | 확보(gofu) | |
| 1280×800 PC ([고정] 핀) | 742×604 | 0.8994 | 0.9176 → −2.0% | 22.5 px | 51.7 × 40.5 | 확보(gofu) | |
| 1920×1080 PC (핀) | 1382×884 | 1.6749 | — | 41.9 px | 96.3 × 75.4 | 확보(gofu) | |

- **iPad 행에 예측이 없는 것은 의도다.** A-12 정정: 확정 배율 0.8914 는 안드로이드
  태블릿 기준 상한이지 아이패드 실측이 아니다. safe-area(홈 인디케이터 약 20px, 노치
  기기 가로 좌우 각 44px)가 **추가로** 빠지므로 실기 확인 전까지 이 숫자를 확정으로
  쓰지 않는다.
- **half/flat(525×450) 행은 2.3 착수 시 이 표에 추가한다**(A-13) — 종횡비가 달라
  narrow 가로에서 세로 제약이 더 심하다.
- 800×480 은 세로가 절대 제약(높이 348)이라 축척이 0.663 에서 멈춘다. 이 기기에서
  체크가 실패하면 답은 레이아웃이 아니라 2단 히트(1.6)·정착 스냅(1.1~1.2)이다 —
  레이아웃 티켓을 만들지 않는다.

## 3. 체크리스트

규칙: 항목마다 ID 를 붙인다(기록 양식 §5 에서 참조). 한 줄에 **관찰 가능한 사실
하나**. 실패하면 그 줄의 ID 와 함께 §5 양식에 기록한다.

### 3.0 스모크 — 기기 확보 즉시, 지금 코드로 검증 가능

기기가 앱을 돌릴 수 있다는 것 자체가 확보 판정의 일부다.

- ☐ **S-1** 태블릿 브라우저에서 §1.2 주소로 열면 첫 화면이 뜬다 (403/타임아웃 아님)
- ☐ **S-2** "홈 화면에 추가" 후 아이콘으로 실행하면 주소창·탭바 없이 전체화면으로 뜬다
- ☐ **S-3** standalone 재실행 시 흰 화면 번쩍임 없이 다크 테마로 바로 뜬다 (index.html 부트 스크립트)
- ☐ **S-4** 트레이의 칩을 손가락으로 코트에 끌어다 놓으면 칩이 놓이고 트레이의 남은 개수가 1 줄어든다
- ☐ **S-5** 코트의 칩을 끌어 옮기고 손을 떼면 칩이 손 뗀 자리 근처에 멈춘다 (원위치로 되돌아가지 않는다)
- ☐ **S-6** 빈 곳 더블탭 후 끌기로 판이 움직인다 (커밋 38f7253 의 판 이동)
- ☐ **S-7** 고무줄 선택을 화면 가장자리까지 끌면 화면이 스스로 밀린다 (커밋 2e347d8)
- ☐ **S-8** 판 하단의 속도 제한 스위치를 손가락으로 토글할 수 있다 (커밋 47257f5)
- ☐ **S-9** 두 손가락 핀치로 줌이 되고, 줌 상태에서 칩 드래그가 여전히 된다
- ☐ **S-10** 태블릿을 가로↔세로로 돌리면 코트가 잘리지 않고 새 방향에 다시 맞는다

### 3.1 항목 2.3 — useIsNarrow + 크롬 예산 (검증 시점: 2차 2.3 랜딩 후)

완료 판정 원문: "half/flat 코트 행 추가(A-13) · safe-area 를 예산에 포함(A-12)".
숫자 대조가 핵심이다 — 스크린샷을 찍고 §2.2 표의 "실측 상자" 칸을 채운다.

- ☐ **N-1** 1024×600 가로에서 풀 코트 825×525 전체가 스크롤 없이 한 화면에 보인다
- ☐ **N-2** 1024×600 가로 스크린샷에서 코트 상자를 재면 907×468 의 ±2% 안이다
- ☐ **N-3** 800×480 에서 풀 코트 전체가 한 화면에 보이고 상자 실측이 683×348 의 ±2% 안이다
- ☐ **N-4** 같은 기기에서 half 코트(525×450)로 바꿔도 코트 전체가 한 화면에 보인다
- ☐ **N-5** iPad standalone 가로에서 하단 홈 인디케이터 띠가 어떤 버튼·스위치와도 겹치지 않는다
- ☐ **N-6** 노치 iPad standalone 가로에서 화면 좌우 끝의 컨트롤이 잘리지 않고 전부 탭에 반응한다
- ☐ **N-7** iPad 의 코트 상자 실측을 §2.2 표에 기록했다 (이 기록이 A-12 의 "확정으로 쓰지 않는다" 단서를 해제한다)
- ☐ **N-8** `--hit` 44↔56 전환(2.4) 전후로 코트 상자 크기가 같다 (스크린샷 2장 대조)

### 3.2 항목 4.3 — revoke 지연 + navigator.share (검증 시점: 4차 4.3 랜딩 후 · **iPad 필수**)

완료 판정 원문: "실기 iPad 확인이 최종 판정 (jsdom 은 no-op)". §6.1d 의 반증 대상은
"Safari 계열에서 다운로드 시작 전 URL 회수로 **저장이 조용히 실패**"하는 형태다 —
그러므로 파일이 "생겼는가"가 아니라 **"열리는가"** 까지 본다.

- ☐ **E-1** Safari 탭 모드에서 [내보내기] 실행 후 파일 앱(또는 다운로드 목록)에 파일이 생겼다
- ☐ **E-2** 그 파일의 크기가 0 바이트가 아니다
- ☐ **E-3** 그 파일을 SPIN 가져오기로 다시 읽으면 성공한다 (라운드트립 — revoke 회귀의 결정적 반증)
- ☐ **E-4** standalone 모드에서 [내보내기]를 누르면 iOS 공유 시트가 뜬다 (아무 일도 안 일어나는 게 아니라)
- ☐ **E-5** 공유 시트에서 "파일에 저장"을 고르면 파일 앱에 실제 파일이 생기고 E-3 과 같이 라운드트립된다
- ☐ **E-6** 내보내기를 연속 2회 실행하면 두 파일 다 라운드트립된다 (revoke 타이밍이 연타에서도 안 깨진다)
- ☐ **E-7** 안드로이드 Chrome 에서도 E-1~E-3 이 성립한다 (share 미지원/거부 시 a[download] 폴백 경로)
- ☐ **E-8** 공유 시트를 "취소"로 닫으면 파일이 생기지 않고 다운로드도 시작되지 않는다 (AbortError 를 실패로 오인해 앵커 폴백이 새는 회귀의 반증 — files.ts 의 isAbortError 분기)
- ☐ **E-9** 데스크톱 Chrome 에서 "다운로드 전에 각 파일의 저장 위치 확인"을 켜고 [내보내기] → 저장 대화상자를 **30초쯤 열어 둔 뒤** 저장해도 파일이 0 바이트가 아니고 E-3 처럼 라운드트립된다 (blob URL 의 fetch 는 대화상자를 닫을 때까지 시작되지 않는다 — REVOKE_DELAY_MS 40초 유예의 실측 상한 검증)
- ☐ **E-10** standalone 모드에서 [내보내기] 탭 → 공유 시트가 **첫 탭에 바로** 뜬다 (한 박자 늦게 뜨거나 두 번 탭해야 뜨면 share 호출 앞에 await 가 끼어 제스처가 만료된 회귀다 — files.ts downloadBlob 의 동기 호출 계약)

### 3.3 항목 4.5 — PDF = 인쇄 (검증 시점: 4차 4.5 랜딩 후)

완료 판정 원문: 인쇄 품질 + §6.3 보험 조항 — "'대상: PDF로 저장' 정밀 조작이
**실기에서** 실제 부담으로 판명되면 PNG 렌더러 재사용 ㉠ 변형으로 승격". 승격 여부를
가르는 판정이므로 **부담을 느낌이 아니라 횟수·성패로 기록한다.**

- ☐ **P-1** 인쇄 미리보기에서 60스텝 드릴 시트가 1페이지로 잘리지 않고 스텝 수만큼 페이지로 나뉜다 (A-11 반증)
- ☐ **P-2** 미리보기에서 코트 배경이 흰색이 아니라 초록(#1f7a46)이다 (`print-color-adjust: exact`)
- ☐ **P-3** 저장된 PDF 에서 한글 제목·스텝 이름·메모가 빈 칸이나 □ 없이 읽힌다
- ☐ **P-4** 저장된 PDF 의 코트 라인을 확대하면 계단 현상 없이 벡터로 보인다
- ☐ **P-5** 세션 계획서의 준비물 줄이 판 위 개체 수와 일치한다 (선수 = 전 스텝 pose 합집합, 공·콘 = cast — A-1)
- ☐ **P-6 (보험 조항 판정)** PC: 인쇄 대화상자에서 "대상: PDF로 저장" 선택을 발 마우스로 첫 시도에 완료했다
- ☐ **P-7 (보험 조항 판정)** iPad: 공유→인쇄→(핀치 또는 프린트 옵션)→"파일에 저장"을 도움 없이 3번 이내 시도로 완료했다
- ☐ **P-8** P-6/P-7 의 실제 시도 횟수와 소요 시간을 §5 양식에 기록했다 — **P-6 또는 P-7 이 실패하면 ㉠ 변형 승격을 발의한다**
- ☐ **P-9** 흑백으로 인쇄(또는 흑백 미리보기)했을 때 두 팀 칩이 구분된다 (4.6 랜딩 후 — 그 전에는 실패가 정상이다)

### 3.4 결정 ⑤ — 판 뒤집기 flip 재검토 트리거 (검증 시점: 시연 화면 실사용 시)

§9-⑤ 원문: "(A) 잘라낸다 — 실기에서 대체재가 부족하다고 판명되면 4차 이후 재검토".
대체재 = '시연 화면 + 태블릿을 물리적으로 돌리기'. 국제 활동 맥락(벽 거치·삼각대·
화면 공유)에서 이 대체재가 성립하는지가 재검토 트리거다.

- ☐ **F-1** 회전 잠금을 켠 채 태블릿을 180° 돌려 맞은편 사람에게 판을 보여줄 수 있었다 (자동 회전이 개입해 판이 되돌아오지 않는다)
- ☐ **F-2** 태블릿을 돌릴 수 없는 자세(벽 거치·삼각대·화면 공유)로 상대에게 설명한 실제 상황이 있었는지, 그때 뒤집기가 없어 설명이 막혔는지를 §5 양식에 기록했다 — **막힌 기록이 생기면 결정 ⑤ (B) 재검토를 발의한다**

### 3.5 입력 경로 실기 확인 (검증 시점: 지금부터 계속 — 릴리스마다 재실행)

§4 의 매트릭스를 실기로 돈 결과다. 각 셀이 아래 ID 하나에 대응한다.

- ☐ **I-1** 발 마우스로 트레이 칩을 코트에 끌어다 놓을 수 있다
- ☐ **I-2** 입 젓가락 키보드만으로 트레이 칩에 Tab 포커스 → Enter 로 무장(arm)이 된다 (1.10 랜딩 후 — 그 전에는 실패가 정상이다)
- ☐ **I-3** 방향키로 선택된 칩이 움직인다 (칩 선택 후 ← → ↑ ↓ 각 1회, 4방향 전부)
- ☐ **I-4** 화살표 개체를 선택하고 방향키로 옮길 수 있다 (1.11 랜딩 후 — 그 전에는 실패가 정상이다)
- ☐ **I-5** Esc 한 번으로 선택이 해제된다 (1.7 랜딩 후)
- ☐ **I-6** 선택이 없는 상태에서 ← → 로 스텝이 넘어간다
- ☐ **I-7** Ctrl+Z 로 되돌리기가 된다 — 그리고 **Ctrl 조합이 입 젓가락으로 실제 가능한지, 불가능하면 어떤 대체(화면 버튼)를 썼는지 기록한다**
- ☐ **I-8** 단일 키 도구 전환(singleKeyMode 'on')이 젓가락 한 타로 된다
- ☐ **I-9** 터치로 칩을 놓고 손을 뗀 뒤 스텝을 넘겼다 돌아왔을 때 칩이 정착 위치에 있다 (1.1 랜딩 후)
- ☐ **I-10** 겹쳐 놓은 휠체어 두 대를 터치로 각각 떼어낼 수 있다 (1.3 랜딩 후)

### 3.6 규칙 화면 — 새 화면 스모크 (검증 시점: 규칙 화면 랜딩 후, 2026-08-21)

로드맵 0.5 항목은 아니지만(버전 미정 후보에서 즉시 착수) 같은 문서에 모아 둔다 — 다른
항목들과 마찬가지로 jsdom 이 못 재는 것(실제 좁은 창 리사이즈·실기기 렌더 체감)이 있다.
gofu 로컬 dev 서버 실기(2026-08-21)에서 R-1~R-3 은 이미 확인됐다 — 아래는 태블릿에서
다시 돌 때의 체크리스트다.

- ☑ **R-1** 왼쪽 레일(또는 좁은 창 헤더 세그먼트)의 [규칙] 아이콘을 눌러 목록이 뜬다 (gofu 확인)
- ☑ **R-2** 제1조를 고르면 필드 규격 도해(정지, 재생 버튼 없음)가 라벨과 함께 그려진다 (gofu 확인)
- ☑ **R-3** 킥오프(제8조)처럼 장면 있는 조항을 고르면 5m 링이 뜨고 [재생]을 누르면 스텝이 자동으로 넘어간다 (gofu 확인)
- ☐ **R-4** 좁은 창(태블릿 세로 등)에서 목록↔상세가 한 번에 하나만 보이고 [← 목록으로]로 되돌아온다 (단위 테스트로만 확인됨 — 실기 대상)
- ☐ **R-5** 발 마우스로 조항 목록 행을 클릭해 상세로 이동할 수 있다
- ☐ **R-6** 처음 여는 기기에서 규칙 화면 튜토리얼(3단계)이 자동으로 뜨고, [도움말]에서 다시 볼 수 있다
- ☑ **R-7** 제2조(공)의 도해 두 장이 뜬다 — 크기 비교(33cm 치수선·축구공 5호)와 공기압 3칸. 밝은·어두운 테마 양쪽에서 확인 (gofu 확인, 2026-08-21)
- ☐ **R-8** 태블릿에서 도해가 있는 조항을 **손가락으로 스크롤**해 끝까지 읽을 수 있다 (도해에 `stage-svg` 를 안 붙인 이유가 이것이다 — 붙으면 `touch-action: none` 으로 스크롤이 죽는다)

## 4. 입력 방식별 통과 조건

같은 기능이 세 경로 **전부**에서 성립해야 통과다. 한 경로라도 비면 그 기능은
"일부 사용자에게 없는 기능"이다 — 주 사용자 본인이 그 일부다.

| 기능 | 마우스 (발) | 터치 (손) | 키보드 (젓가락) | 검증 시점 |
|---|---|---|---|---|
| 개체 배치 | 트레이에서 끌어다 놓기 | 트레이에서 끌어다 놓기 | Tab → Enter 무장 → 코트에 배치 | 키보드는 1.10 후 |
| 개체 선택 | 클릭 | 탭 | Tab 포커스 | 지금 |
| 개체 이동 | 드래그 | 드래그 | 방향키 (화살표 개체는 1.11 후) | 지금 |
| 선택 해제 | 빈 곳 클릭 | 빈 곳 탭 | Esc | Esc 는 1.7 후 |
| 스텝 이동 | 스텝 칩 클릭 | 스텝 칩 탭 (히트 ≥44px 는 2.10 후) | ← → (선택 없을 때) | 지금 |
| 되돌리기 | 헤더 버튼 | 헤더 버튼 (≥44px) | Ctrl+Z | 지금 |
| 줌 | 휠/버튼 | 두 손가락 핀치 | Ctrl+`+` / Ctrl+`-` / Ctrl+0 | 지금 |
| 판 이동 | 더블클릭 후 끌기 | 더블탭 후 끌기 | Ctrl+방향 | 키보드는 2.6 후 |
| 도구 전환 | 툴레일 클릭 | 툴레일 탭 | 단일 키 (singleKeyMode) | 지금 |
| 내보내기 | 하단 [내보내기] 클릭 | 하단 [내보내기] 탭 | Tab → Enter | 4.7 후 |

기록 규칙:

- 각 셀은 §3.5 의 I-* 항목으로 실기 확인하고, 실패 셀은 §5 양식에 기기·경로와 함께 적는다.
- **수식키 조합(Ctrl+…)은 입 젓가락 사용자에게 두 배 이상 비싸다.** 조합 키가 유일한
  경로인 기능이 발견되면 그 자체를 결함으로 기록한다 (화면 버튼 대체가 있어야 통과).
- 터치 셀의 통과 기준에는 §5.4 의 타깃 크기(44px, largeTargets ON 시 56px)가 포함된다 —
  "맞히려고 두 번 이상 탭했다"는 실패로 기록한다.

## 5. 기록 양식

한 번의 실기 세션마다 아래 머리표 1개 + 항목 행 n개를 이 문서 끝(§5.2)에 누적한다.
스크린샷은 `docs/field-tests/YYYY-MM-DD-<기기별칭>/<항목ID>.png` 로 저장하고 경로를
행에 적는다 (예: `docs/field-tests/2026-08-20-galaxy-tab/N-2.png`).

### 5.1 양식

```markdown
#### 실기 세션 YYYY-MM-DD — <기기별칭>

- 기기: (예: Galaxy Tab A9 8.7", 1340×800)
- OS / 브라우저: (예: Android 14 / Chrome 127)
- 실행 모드: 브라우저 탭 | standalone(홈 화면 추가)
- 접속: (예: http://cube.tail4fa6d9.ts.net:4173 — preview)
- 앱 버전 / 커밋: (화면 표기 버전 또는 git 커밋)
- 입력 수단: (예: 손가락 / 발 마우스 / 입 젓가락 + 블루투스 키보드)

| 항목 ID | 결과 | 스크린샷 | 메모 (시도 횟수·소요 시간·실패 양상) |
|---|---|---|---|
| S-1 | 통과 | — | |
| N-2 | 실패 | docs/field-tests/…/N-2.png | 실측 891×455 — 예측 대비 −1.8% |
```

- 결과는 **통과 / 실패 / 보류** 셋 중 하나만 쓴다. 보류는 "해당 로드맵 항목 미랜딩"
  하나의 사유만 허용한다.
- 실패 행에는 스크린샷이 **필수**다. 통과 행은 숫자 기록이 있는 항목(N-2, N-3, N-7,
  P-8)만 필수.
- P-6/P-7/F-2 처럼 "발의한다"가 붙은 항목의 실패는 기록으로 끝내지 않는다 —
  `docs/PLAN-2026-08.md` 해당 절에 재검토 발의를 남기는 것까지가 기록이다.
